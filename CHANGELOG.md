# Changelog

All notable changes to the Agit8or Connect specification, vectors, schemas, SDKs and conformance suite.
Protocol versions and SDK versions are explained in the README's versioning policy.

## [Unreleased]

### Added

- `docs/SECURITY_AND_READINESS_AUDIT.md`: repository audit of 1.1.0 (findings F-01 … F-25 with severities,
  documented-versus-implemented differences, test gaps). Self-review, not an independent audit.
- Approved-destination `GuardedTransport` in both SDKs (`transport.py`, `transport.ts`) with `DestinationPolicy`
  stores (memory, SQLite; PostgreSQL in Python), integrity digests, Security Blocked state, reviewed address
  changes with distinct approvers and bounded migration overlap, SPKI pins, private-CA-only trust, one deadline,
  request and response caps, certificate-expiry warnings and `preview_destination` (Python).
- `addresses` module in both SDKs: explicit, runtime-independent address classification
  (new vector file `test-vectors/addresses.json`, which also pins the destination digest across SDKs).
- Persistent stores (`agit8or_connect.storage`): replay, rate limits, destinations, elevated-grant and per-action
  approvals on SQLite (WAL, `BEGIN IMMEDIATE`) and PostgreSQL (psycopg 3); TypeScript SQLite stores on `node:sqlite`.
  Every storage failure refuses the request (`*_unavailable`, 503).
- Shared, sliding-window `RateLimiter` (both SDKs) with default rules for pairing, Quick Connect, token,
  authentication, signature failures and approvals; `Retry-After` on 429.
- Elevated-grant policy (`approvals`): two distinct administrators re-authenticated within 5 minutes, bound to a
  request fingerprint, re-checked at token issue and every use, revocable at once. Per-action approval
  `action-approval/1` (PROTOCOL §7.4): single use, bound to target, action and parameter digest.
- Private-key envelope (`keystore`, both SDKs): AES-256-GCM, row-bound associated data, master-key rotation and
  rewrap, file/environment key providers with permission checks, secret temp files (new vector file
  `test-vectors/key-envelope.json`).
- TypeScript: `authenticateResourceRequest` and a scope `Catalog`.
- Tests: security regressions for the audit findings, real TLS on 127.0.0.1 with test-only CAs
  (`typescript/test/fixtures/tls`, regenerated by `tools/make_tls_fixtures.py`), multi-process store races, and
  hypothesis property tests. CI installs hypothesis and runs the store tests against a PostgreSQL service.

- P1 host modules (Python): `proxy` (trusted-proxy client address), `sources` (two-layer source policy, binding
  check, change preview, rollback check, fail-closed cache), `lifecycle` (state machine, failure classes,
  reconnect ladder and circuit breaker, health hysteresis), `storage.SqlEventQueue` (durable outbox),
  `storage.SqlAuditLog` and `storage.SqlSourcePolicyStore`, audit `redact` / `sign_checkpoint` / `verify_export`.
- Negotiated extensions `dpop-nonce/1`, `actor/1`, `action-approval/1` (PROTOCOL §18) in both SDKs and the
  reference peer (opt-in via `ReferencePeer(extensions=...)`); new vector files `extensions.json` and
  `audit-checkpoint.json`; schema `AuditCheckpointClaims`; optional `act` / `nonce` claims in the token and
  proof schemas; `approval_id` in the error schema.
- TypeScript: `TrustedProxyResolver`, `NonceIssuer`, `validateActor` / `actorOf`, `verifyCheckpoint`,
  `verifyAuditExport`; `buildDpopProof({nonce})` and `verifyDpopProof({nonceCheck})`.
- Real-network harness (`agit8or_connect.harness`, `tests/test_harness.py`): two installations with two worker
  processes each over HTTPS on 127.0.0.1, persistent state with encrypted keys, a restart, a DNS change that
  security-blocks, the kill switch, and the TypeScript SDK as a second caller (`typescript/test/harness_client.ts`).
- `docs/PRODUCTION_DEPLOYMENT.md`.
- P2: security CI (`.github/workflows/security.yml`: CodeQL, secret scanning, pip-audit, dependency review,
  OpenAPI validation, schema / vector compatibility, SBOM), hash-locked `requirements/*.txt` used by all CI jobs,
  Dependabot, a release workflow that only drafts a release from an owner-pushed tag, `tools/check_schema_compat.py`,
  property-based fuzz tests for token verifiers and proxy / source inputs.
- P2 docs: `QUICK_CONNECT_UI.md` (screens and workflow contract), `SECURITY_ARCHITECTURE.md`,
  `INTEGRATION_CHECKLIST.md`, `COMPATIBILITY_MATRIX.md`, `PRODUCTION_READINESS.md` (feature status, evidence,
  roadmap); CLAUDE_INTEGRATION_GUIDE shared-state rules.
- Reference peer serves `GET /connect/v1/customers` (audit D-9).

### Changed

- PROTOCOL §2: private keys at rest **MUST** be encrypted (was SHOULD). No message changes.
- PROTOCOL §14.1 (audit checkpoints, exports, redaction) and §18 (negotiated extensions) added.
- Reference peer client accepts both error forms from the token endpoint (a kill switch answered in the protocol
  form produced a malformed error code).
- PROTOCOL §7.3: second-approval rules spelled out (distinct accounts, re-authentication, re-check on use).
- PROTOCOL §13: error codes `action_approval_required`, `replay_store_unavailable`, `rate_limit_unavailable` and
  the client-side transport codes listed.
- Reference peer: discovery is read when an administrator approves, not at pairing submit; pairing requests are
  recorded for replay only after the code matches; events are checked for type and authorisation before their id
  is recorded; unknown and inactive clients get the same token error; retiring keys are refused after the overlap
  and wiped; remote key rings refresh when their endorsement expires; health includes `installation_id`; 401
  responses carry `WWW-Authenticate`; kill switch and `suspended` state.
- `source_in_egress` / `sourceInEgress` compare IPv4-mapped sources as IPv4.
- In-memory replay stores are pruned over time and bounded (single process only).
- The 12 existing vector files are unchanged.

## [1.1.0] - 2026-11-21

First public release of the standard repository. Draft; not independently security-reviewed.

### Added

- `docs/PROTOCOL.md` — `agit8or-connect/1` (draft 1).
- `docs/QUICK_CONNECT_SPECIFICATION.md` — revision 1.1: `qc-bootstrap/1`, `qc-source-binding/1`, `qc-diagnostics/1`.
- Implementation guides: `QUICK_CONNECT_IMPLEMENTATION.md`, `IP_ALLOWLIST_AND_BOOTSTRAP.md`, `CONNECTION_HEALTH.md`,
  `AUTO_RECONNECT.md`, `THREAT_MODEL.md`, `CLAUDE_INTEGRATION_GUIDE.md`.
- `openapi/openapi.yaml` (OpenAPI 3.1) and `schemas/` (23 JSON Schemas, generated by `tools/build_schemas.py`),
  including schemas for the v1 JWS claim sets.
- `test-vectors/` — 12 vector files (7 for v1, 5 for revision 1.1), pinned in `conformance/VECTORS.sha256`.
- Python SDK `agit8or_connect` 1.1.0 with the in-memory reference peer and the vector generator.
- TypeScript SDK `@agit8or/connect` 1.1.0 (`node:crypto` only).
- Conformance suite: vector digests and regeneration, schema checks, both SDKs on the vectors, reference-peer
  interop across the 1.0/1.1 matrix, probe shape / authentication / 404 fallback, optional live checks.
- Examples: minimal Python and TypeScript peers.
- CI workflow running all of the above.

### Changed

- Errata: a discovery capability entry is keyed `scope` (as the Python SDK and the reference implementation
  emit and parse it). Earlier draft text and the OpenAPI `Scope` schema said `name`.
- The Python SDK's `default_transport()` always returns `MinimalGuardedTransport`; host-specific transport adapters
  are not part of the public SDK.
