# Agit8or Connect

A self-hosted way for two applications to trust each other: no central service, no shared secret typed into two
screens. Each pair of installations creates a **connection** with its own Ed25519 keys; the administrators on both
sides approve what each side may do and which customers it may reach. After pairing, calls use short-lived
DPoP-bound OAuth tokens and events are signed webhooks.

This repository holds the open specification, reference SDKs (Python and TypeScript), byte-exact test vectors,
JSON Schemas, an OpenAPI description and a conformance suite.

> **Status: draft — not yet independently security-reviewed. Do not describe this protocol, the SDKs, or an
> implementation built on them as production secure.** The protocol has one host implementation so far (a reference
> implementation is Clientst0r) and no independent second implementation. Feedback and review are welcome; see
> [SECURITY.md](SECURITY.md).

## Protocol at a glance

| Part | Status | Document |
|---|---|---|
| `agit8or-connect/1` — discovery, pairing (code + SAS), tokens (`private_key_jwt` + DPoP), endorsed JWKS, tenant grants, signed events, rotation, revocation, audit chain | draft 1 | [docs/PROTOCOL.md](docs/PROTOCOL.md) |
| Revision 1.1 — Quick Connect: `qc-bootstrap/1` (browser-mediated pairing with a signed invitation, PKCE and DPoP), `qc-source-binding/1` (signed egress declarations, `source_not_authorised`), `qc-diagnostics/1` (`qc_probe`) | draft, optional, negotiated | [docs/QUICK_CONNECT_SPECIFICATION.md](docs/QUICK_CONNECT_SPECIFICATION.md) |

Revision 1.1 is additive: nothing in v1 changes, and a 1.0 peer keeps working with a 1.1 peer over the v1 code flow.

## Running the tests and the conformance suite

Requirements: Python ≥ 3.10 with `cryptography` and `PyJWT` (`PyYAML` optional), Node ≥ 22.18. No network access
and no npm packages are needed.

```bash
pip install "cryptography>=42" "PyJWT>=2.10" PyYAML

# Python SDK
cd python && python -m unittest discover && python -m agit8or_connect.tools.generate_vectors --check && cd ..

# TypeScript SDK
cd typescript && npm test && cd ..

# Vector identity (also part of the conformance suite)
cd test-vectors && sha256sum -c ../conformance/VECTORS.sha256 && cd ..

# Conformance (set CONFORMANCE_REQUIRE_NODE=1 to fail instead of skip without Node)
cd conformance && python -m unittest discover -v && cd ..

# Optional: read-only checks against a running installation
cd conformance && AGIT8OR_CONNECT_TARGET=https://connect.example.com python -m unittest test_90_live -v
```

See [conformance/README.md](conformance/README.md) for what each part proves.

## Versioning policy

- **Protocol major version** (`versions` in discovery, `agit8or-connect/1`): changes only when a message, claim,
  signing string, endpoint or meaning changes incompatibly. Peers pick the highest common major version.
- **Protocol revision** (`revision: "1.1"`): informative. New behaviour arrives as **named, versioned extensions**
  (`qc-bootstrap/1` …) that are used only when both sides advertise them. Receivers MUST ignore unknown members, so a
  revision never breaks an older peer.
- **Test vectors** are part of the specification. Existing vector files never change bytes within a major version;
  a revision adds new files. `conformance/VECTORS.sha256` pins every file.
- **SDK versions** (`python/pyproject.toml`, `typescript/package.json`) follow semantic versioning and track the
  protocol revision they implement (`1.1.x` implements revision 1.1).
- Each release is listed in [CHANGELOG.md](CHANGELOG.md).

## Known limitations

- Not independently security-reviewed; no independent second implementation yet.
- The TypeScript SDK builds and verifies messages but has no guarded HTTP transport; bring your own client that
  follows [IP_ALLOWLIST_AND_BOOTSTRAP.md §4](docs/IP_ALLOWLIST_AND_BOOTSTRAP.md#4-outbound-approved-destinations).
- The Python `MinimalGuardedTransport` enforces address, TLS, redirect and proxy rules but has no
  approved-destination store; hosts add the pin.
- The reference peer is in-memory test code (no sockets, no persistence) and has no TypeScript counterpart.
- Delegated-user (actor) claims, per-action approval for high-risk scopes and event forwarding across more than two
  applications are design notes only ([PROTOCOL.md §17](docs/PROTOCOL.md)).
- The signed vector messages carry example application `type` / `display_name` values from the original vector
  generation. They are opaque test strings; changing them would change every signature.
